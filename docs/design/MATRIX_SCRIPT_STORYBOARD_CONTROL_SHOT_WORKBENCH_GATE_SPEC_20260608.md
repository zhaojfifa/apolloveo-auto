# Matrix Script — Storyboard Control + Shot Workbench Gate Spec (2026-06-08)

Status: **ACCEPTED-PENDING-SIGNOFF GATE SPEC — docs-only. Implementation gate for the
Matrix Script Storyboard Control + Shot Workbench wave (the first script-directed
generation wave). Implements nothing itself. The implementation gate is CLOSED until
the §19 signoff (Architect + Reviewer + Owner) merges to `main` and the Owner grants
S5→S6.**

Derivation: authored under Owner decision 2026-06-08 ("APPROVE S5 for Matrix Script
Storyboard Control + Shot Workbench Gate Spec authoring") against the accepted
Storyboard-to-Video Architecture Alignment. It freezes that alignment into enforceable
engineering rules. It is the **first gate spec authorized to cross into script-directed
generation** (Prompt Builder → Akool payload) — a boundary the Slot Workflow v2 gate
spec and the ffmpeg backbone gate spec explicitly forbade for their (presentation /
local-only) scopes. It **does not** author a new Information Architecture and **does
not** supersede Bucket A.

When this gate spec conflicts with Bucket A authority
(`docs/design/MATRIX_SCRIPT_DESIGN_AUTHORITY_INDEX.md` §A) or root governance
(`ENGINEERING_RULES.md`, `CURRENT_ENGINEERING_FOCUS.md`), the underlying authority wins
and this spec is corrected in a docs-only follow-up.

## 1. Purpose

Freeze the rules that turn Matrix Script from a **provider-connectivity** result
(image-motion clip over a still, hardcoded prompt) into a **script-directed
Script-to-Video** result: the operator sees a storyboard, reads/edits the per-shot
generation intent, and one shot is generated by Akool from a **script-derived** prompt
+ hosted material, consumed into `final.mp4` — while every merged behavior is preserved
(Azure voiceover, burned subtitles, V1/V2 protection, delivery-follows-confirmed-main,
`official_publish_ready=false`).

The model the implementation must teach (re-homed into the existing A–J Workbench, no
new IA, no parallel flow):

> 看 V1 → 扫描分镜队列（Storyboard Queue）→ 打开当前镜头（Current Shot Work Panel）
> → 读/改 该镜头的生成要求（AI 生成要求 / 负面约束 / 素材角色）→ 重新生成这个镜头
> （脚本派生 prompt + 已托管素材 → Akool）→ 对比 V1/V2 → 确认主版本 → 交付

This spec is **gate-spec-first**. No runtime PR may open until §19 signoff merges; each
slice (§15) is then its own Owner-gated S5→S6 (L3) decision.

## 8. Prompt Builder (binding)

A **pure, deterministic** backend function (no network, no secret, no clock,
no `Date.now`/random); same inputs → same outputs.

- **Inputs:** `script_segment`, `narration_line`, `visual_goal`, `motion_instruction`,
  `material_role` (§9), `selected_material` (friendly label + role + commercial status),
  `duration_seconds`, `aspect_ratio`.
- **Outputs (three, audience-separated):**
  - **(a) operator-safe AI 生成要求 + 负面约束** — operator language; **no vendor name, no
    secret, no raw URL, no raw handle**. This is what §7 renders/edits.
  - **(b) provider payload prompt + negative prompt** — assembled at call time; **never
    surfaced to the operator**; passed to `generate_shot_clip_akool(..., prompt=…)`,
    **replacing** the hardcoded `DEFAULT_PROMPT` (`akool_image_to_video_capability.py:80,198`)
    for the controlled shot.
  - **(c) diagnostic summary** — operator-language one-liner for the queue / §J (e.g.
    "镜头2 · 产品特写 · 使用产品素材 · 推近运动"); raw payload only in §J.
- **PB-1.** The function MUST be unit-tested for determinism and for the no-secret / no-raw-URL
  / no-vendor-name guarantee on outputs (a) and (c).
- **PB-2.** Material role (§9) MUST drive the preservation clause and the matching negative
  constraints (e.g. `product_reference` ⇒ preserve product shape/color/label + negative
  "distortion, warping, label change").
- **PB-3.** The tomato pilot MUST bind the tomato bowl as `product_reference`; the
  controlled shot's prompt is built from the script segment + visual goal + motion + that
  role — not `DEFAULT_PROMPT`.

(Worked examples — product close-up + lifestyle eating — are frozen in alignment doc §10.)

## 10. Controlled Akool Regeneration (binding)

- **AK-1.** **At least one shot** MUST use a **script-derived prompt** (Prompt Builder output
  b) + the **hosted material URL** (existing presigned R2 path) — not `DEFAULT_PROMPT`.
- **AK-2.** The Akool-generated clip MUST be **downloaded + normalized to backbone spec
  (1080×1920/30fps h264)** and **consumed into `final.mp4`** (existing
  `akool_image_to_video_capability` download/normalize + `ffmpeg_backbone` compose path).
  The raw provider URL is discarded after download — never persisted as delivery, never
  operator-visible.
- **AK-3.** Other shots MAY fall back (ffmpeg proxy → static still); fallback is honest,
  operator-language, per-shot evidence — never a vendor error, never a broken clip.
- **AK-4.** **Azure voiceover MUST remain audible** and **subtitles MUST remain visible**
  (burned + sidecar) in `final.mp4`.
- **AK-5.** Gated by `MATRIX_SCRIPT_AKOOL_REAL` + credential presence (`akool_real_gate`);
  bound to one controlled shot per task to cap cost; `official_publish_ready=false`.
- **AK-6.** Provider hardening (poll/timeout tuning, error taxonomy, concurrency limit,
  credit/cost guard) is RECOMMENDED in the PR-4 slice and REQUIRED before any broad rollout;
  the gate spec does not authorize multi-shot or unbounded provider calls.

## 11. Route Decision (binding) — **Option A chosen**

**Decision: Option A — reuse the existing whole-task regenerate route with an active-shot /
provider-target designation; NO new route in this wave.**

- The existing route `POST /api/matrix-script/{task_id}/tomato-real-result`
  (`gateway/app/routers/matrix_script_tomato_real_result.py:65` → `run_tomato_real_result(...)`)
  and `POST /matrix-script/{task_id}/regenerate-preview` (`gateway/app/routers/tasks.py:1087`)
  are reused.
- The **service** `run_tomato_real_result` (`tomato_real_result_orchestrator.py:396`) is
  generalized so the **active shot** (from the Current Shot Work Panel) is the designated
  provider-target — replacing the hardcoded `AKOOL_SHOT_ID = "shot02"`
  (`tomato_real_result_orchestrator.py:85`) — and so the **Prompt Builder output (b)** is
  passed to `generate_shot_clip_akool(..., prompt=…)` instead of `DEFAULT_PROMPT`. Material
  flows through the existing `material_overrides` parameter (`…:407`).
- The **router stays thin** (`ENGINEERING_RULES.md` §3): the only allowed router touch is
  **request-parsing** of the active-shot id (and optional prompt-intent), passed straight to
  the service. **No business orchestration, no media flow, no truth derivation in the
  router.** No new endpoint, no route-behavior change beyond thin additive parsing.
- **重新生成这个镜头** operator semantics are satisfied by designating the active shot as the
  provider-target on the existing route.

**Option B (a new per-shot regenerate route) is DEFERRED and forbidden in this wave.** If
per-shot isolation later proves necessary, it requires a **separate gate-spec amendment**
that freezes the exact new path + a thin router/service boundary; it is out of scope here.
